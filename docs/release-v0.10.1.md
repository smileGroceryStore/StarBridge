# v0.10.1 配置与恢复排查

2026-10-17。修复重复应用配置覆盖原恢复点的问题。

- OpenCode、Pi、Reasonix：目标文件内容与上次应用相同时不重复写入、不创建新恢复点，保留原有恢复备份。仍会核对预览是否过期、文件是否外部改动及是否有未完成操作。
- Reasonix：生成后的 TOML 数据不变时保留原文，避免重复应用累计空行、改变注释格式并触发伪变更。
- 非 UTF-8 配置在读取时停止操作并提示检查编码，防止解码替换字符导致备份无法按原字节恢复。UTF-8 BOM 不会被读取阶段静默移除；各适配器仍执行原有格式检查。
- 更新兼容性清单的 Reasonix Studio 条目，移除过时的身份待确认标记。

验证覆盖核心回归、三个工具连续重复应用后恢复原文件、异常字节保护、Reasonix 跨协议模型收缩和旧凭据清理，以及安装包内桌面预览、重复应用、恢复与托盘退出流程。测试使用临时配置及虚拟凭据，不调用推理接口。

结果：44 项核心测试通过；安装包内三个工具均通过首次应用、重复应用保留原备份和恢复流程，桌面测试退出码为 0。Reasonix 本机原生引擎识别全部三种协议与虚拟凭据。静默升级到 0.10.1 后，真实连接库、Reasonix 配置和凭据文件的校验和均保持不变。

后续补充优先级：

1. 新增 Claude Code / Codex 写入适配时，先验证安装版本、配置协议、环境变量优先级和恢复流程；当前工具目录收录与模型预设不代表已经写入这些工具。
2. 提供按模型的验证记录和用户主动触发的批量检查，明确可能消耗额度；目前连接只展示最近一次模型检查结果。
3. 支持受控的配置合并：目前目标文件有外部变化会阻止整文件恢复，仍需人工核对；后续可提供字段差异与逐项选择。
4. 配置目录迁移向导：变更外部配置目录后，恢复旧目录文件可能需要重新选择旧路径；后续增加原目录提醒与明确的恢复入口。
