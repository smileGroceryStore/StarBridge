# v0.8 排查及 CC Switch 对照

日期：2026-10-17。只读检查代码并在独立临时目录使用虚构密钥复现；未更改真实 Agent 文件、未发起真实推理请求、未修改安装版。

## 已复现的问题

1. **应用回滚未同步恢复活动记录（P1）**。让目标文件正常写入，在活动记录已保存后、备份阶段更新为 applied 时注入一次失败：文件回滚完成，返回“已回滚本次写入”，但工具状态为 external-change。应保存原活动记录，并将文件与活动记录一起回滚；若元数据恢复失败，保留可发现的恢复记录。位置：src/config-engine.js 的 apply。
2. **Pi 可选模型缩减后残留旧模式（P1）**。settings.enabledModels 已存在时，先应用 m1/m2，再仅保留 m1，旧 /m2 模式仍在 enabledModels 中。应清理本连接托管模式再合并本次列表，保留其他提供商及用户模式。位置：src/config-engine.js 的 Pi preview。
3. **模型诊断可能误报成功（P1）**。HTTP 200，响应为 {"choices":[{}]}，返回 model-ok。当前只检查任一候选数组非空，未按请求协议验证内容。应按协议检查有效消息、文本或合理结束状态，区分格式错误、无可见输出、认证、限流和模型不存在；保持响应脱敏。
4. **连接地址和模型覆盖地址缺少继承说明（P1，交互问题）**。为 m1 保存旧模型地址后修改连接 Base URL，新连接地址成功保存，但 m1 仍使用旧模型地址。这符合现有覆盖规则，却容易让用户以为连接修改已对所有模型生效。应明确“继承连接 / 独立覆盖”，显示实际生效端点，并提供重置继承和影响预览。

现有 26 项测试通过，以上新场景尚未包含在现有回归测试中。

## 对照 CC Switch 的下一批工作

参考官方 README 的功能矩阵、供应商管理和配置存储说明，而非搜索结果中的第三方副本：

- https://github.com/farion1231/cc-switch/blob/main/README_ZH.md
- https://github.com/farion1231/cc-switch/blob/main/docs/user-manual/zh/README.md

建议次序：

1. 修复上述四项，增加提交元数据失败、模型缩减和协议响应校验回归测试。
2. **工具现有配置导入**：将此前一次性迁移做成产品入口；预览连接和模型、去重、默认隐藏密钥，不自动应用。
3. **真实适配与能力矩阵**：优先核验 DeepSeek Harness / ZCode，再补常用 Agent；逐工具明确切换还是供应商共存、模型覆盖规则、验证版本与实际写入位置。
4. **配置位置设置**：支持自定义目录、项目级配置和 WSL 的明确选择；先解决定位与覆盖关系，再做批量应用。
5. **供应商 / Coding Plan 模板库**：官方端点、地区、计费类型、模型协议、核验时间分开建模；不把服务商营销信息当作兼容性依据。
6. **桌面快捷操作**：托盘、收藏排序、最近使用、保存切换方案；依旧先显示影响范围，避免点击启用却不知道哪些工具被改变。
7. **按需求后续扩展**：加密同步与冲突预览；MCP / Skills / 提示词统一管理；用量与套餐到期提醒。账户真实余额与本地估算分开显示。

CC Switch 区分切换型工具和供应商共存型工具，星桥也应沿用这种能力建模，而非为所有工具套用一个启用开关。当前星桥实际写入适配仍仅 OpenCode / Pi。

本地代理、协议转换及自动故障转移可后置：它们会改变请求路径、计费归属和运行依赖，需要单独设计与验证。
